# Link collision records and normal-hit details

This pass adds exact two-dimensional capsule checks and per-region launch selection for the verified static top-bone records in Link's three jabs, forward air, and down tilt. A Matter rectangle supplies broad collision events; the handler then tests the authored circles/capsules against tangible hurtboxes. Empty corners of that rectangle no longer count as hits. Overlapping records use the lowest eligible source ID, with separate ground/air eligibility. Existing attack-instance and hit-group confirmation still prevents one swing from hitting the same victim twice.

Coordinates use the project's existing scale of 5 px per source unit and the baseline Link foot at body center +36 px: `x = sourceZ * 5 * facing`, `y = 36 - sourceY * 5`. The selected top-bone records have zero depth. This is an explicit static 2D projection; it does not reproduce animated skeletal transforms or native three-dimensional hurtboxes.

The damage handler currently registers fighter recipients. Both authored `fighter` and `all` category records can therefore contact those recipients, and the overlapping lower-ID fighter tip wins. This pass does not add attacks against items or other native target categories. All implemented records belong to source part zero; nonzero parts are rejected by the authoring parser because their separate priority behavior is not implemented.

Every audited Link normal now carries its source hitlag and SDI factors. A hit-window or collision record can override these factors, including zero, and the selected values survive sensor delivery, save/load, the character factory, and Lab numeric edits. Reference damage-only charge scales explicit per-region damage once while preserving launch records. The shared combat pass separately owns hitlag duration, effective stale damage, crouch behavior, and outgoing attacker freeze.

The Lab preview draws the authored capsules instead of the inactive fallback rectangle, follows the selected strike's fields, highlights the selected region, and fits the combined body and attack bounds into its panel. The grounded-normal diagnostic helpers likewise report the live capsule envelope dimensions, keeping their positions and sizes consistent with actual sensors.

Authoring also preserves the special-phase records and optional defense profiles implemented by the sibling passes: reference damage-only arrows, late/return boomerang records, per-rung Spin launch/modifier/lifetime arrays, trap launch/modifier settings, and neutral/directional/backward dodge timings. Missing saved profiles inherit the shipped fighter defaults. Partial defense windows are validated against their effective inherited values; facing reversal can occur during recovery.

## Sources and unresolved native behavior

[sources/provenance.json](sources/provenance.json) pins the dumped-script commit, exact URLs, retrieval date, and SHA-256 hashes. The local Attack11/12/13, AttackAirF, and AttackLw3 files provide the numeric records above. The [UFD renderer legend](https://ultimateframedata.com/smash) documents lower-ID priority for overlapping hitboxes within a part; its captured page is included. This is sourced renderer documentation, not a claim that this repository contains a native collision-engine decompilation.

The pinned [smash-rs attack bindings](sources/smash-rs-attack.rs) and [damage bindings](sources/smash-rs-damage.rs) expose attack position, speed, target position, and launch-related fields. They do not provide the engine implementation of angle367. No formula was inferred solely from the numeric angle or invented to make a combo connect. Native animated sword/arm/knee positions, the omitted bone-bound spatial variants on other normals, nonzero hitbox parts, native hurtbox animation, and complete native attack-category filtering remain unresolved. Existing representative launch records for those moves remain in place.
