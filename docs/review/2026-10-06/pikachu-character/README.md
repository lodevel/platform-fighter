## Coordinates, anatomy and equipment

Pikachu is a short mouse with head, two ears, torso, forepaws, hind feet and a bent lightning-shaped tail. There is no intrinsic held equipment. Tail bones, knee/hip and neck are distinct native contact parts. Temporary carried items retain the existing item attachment/renderer route. Thunder Jolt, cloud, bolt and self-contact burst are spawned effects/objects rather than permanent body equipment.

Runtime simulation uses a fixed 60 Hz step, right/down screen axes and a facing sign. Inclusive source game frames `s..e` map to elapsed `[s-1,e)`. Historical script clocks are motion frames; GIF delays/image indices are not gameplay frames. A finite script region `[frame,end_frame)` maps to elapsed `[frame-1,end_frame-1)` only after its motion-rate mapping is checked. Preserve clear gaps and geometry changes even when damage stays the same.

The established project reference scale is 5 world pixels per native distance unit. Root-bone projection uses native `z` forward and `y` up, with the simulation-root offset recorded separately. Native lateral `x` depth cannot be reproduced by simply placing it on the forward axis. Non-root `kneel`, `hip`, `tail1/3/4`, `neck` and `trans` records require inspected posed transforms/retargeted anchors; there is no generic substitute anchor. Generated pixels never establish native numeric radius or launch data. The identity reference now has authored root/body registration below; animated hurtboxes still require separate pose authoring.
