# Quick Attack status contract preparation

Scope: inspection of the preserved vanilla status and ACMD captures. This is an implementation contract for subsequent work, not a running recovery, a selected numeric parameter bundle or proof of native clock parity. The new Ultimate-specific parameter-table acquisition must retain its export provenance and exact units before adoption. Existing single-burst `directionalJump` behavior does not implement this contract.

Independent preparation now has two explicitly named input bundles: exact historical table cells and actual typed values from the acquired Pikachu PRC test fixture. [The binary/table comparison](native-vl-prcrs-sheet-comparison.json) matches78 scalar fields at native storage precision. The second multiplier is table0.9 versus actual Float32`0x3f666666`/0.8999999761581421; these remain distinct rather than silently rounding the binary. The fixture's patch and unmodified extraction provenance are unknown, so neither bundle enables production movement. [Preparation evidence](quick-attack-preparation.json) compares original CSV/binary bytes, not just generated module constants.

The captures belong to the pinned status revision recorded in [status verification](status-verified.json) and the pinned ACMD revision in [source overview](README.md). Native motion frames, status update order and runtime elapsed frames are different clocks; matching one parameter does not establish their boundary mapping.

The exact second-burst angle inequality is `<` after converting the configured degrees to radians. A numeric35degree table value therefore means a35degree turn is rejected; values just above35 may pass if the stick threshold and phase also pass. This statement is conditional on that exported value being qualified for use.

Remaining clock questions include startup motion end versus first warp-loop execution, counter initialization versus the first decrement, ACMD frame9 versus END exec ordering, and the motion/gameplay timing discrepancy already retained in the source inventory. Native gravity/control APIs also need their source common-fighter parameters and unit conversions rather than copied roster constants. No runtime special or claimed recovery distance has been added by this inspection.

Required acceptance after implementation: both facings, neutral/up/down/horizontal/diagonal raw stick, magnitude just below/at/above the threshold, turns below/at/above the angle threshold, a rejected branch followed by later valid input, no third burst, individual burst damage/dedup, hitlag/pause, walls/ceiling/one-way platforms/ledges, launched offstage recovery, helpless touchdown, capture/damage/death interruption and saved-fighter transport. Input simulation and fixture bodies must remain explicit in their evidence.
