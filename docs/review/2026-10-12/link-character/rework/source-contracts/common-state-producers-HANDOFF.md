Current integration sites are `MatchScene`'s recovery pickup gate and `Character.beginItemRecovery`, `canUseItemsBeforeInput`, prone input branch and `applyHit`. The first two reject knockdown; the prone branch consumes attack as getup; `applyHit` clears prone state and relaunches every new hit. There is no existing jablock reducer to reuse. A separate source-priority jablock contract must preserve bound admission, orientation and a two-lock counter, then return to all prone getup options; Ultimate does not force neutral getup. Exact native lock thresholds/window/selectors remain unresolved.

HDR's retained common hooks corroborate Food priority and identify DownDamage as jablock. They are modifications: their altered jablock exit and parameter values are excluded as vanilla evidence. The pinned status dump lacks lua2cpp_common, and the retained fighter workbook has no common sheet. Neither missing common code nor an inactive current producer removes a required receiving row.

All leases need simulation clocks, frozen-frame behavior, generation guards, replay serialization and stock/reset/destruction cleanup. These are integration obligations for the runtime owner, not completed match verification.
